# Editions and commercial support

DxTools is distributed under GNU GPL v2 (`GPL-2.0-only`). The license permits
use, study, modification and redistribution for any purpose, including
commercial. The editions therefore differ not in software rights but in the
level of support and related services.

This document describes the offering and is not a public offer: the scope of
services, pricing and liability are fixed in the contract.

Русская версия: [commercial.md](commercial.md).

| | |
|---|---|

Community is the full-featured build. It has no cut-down features, license
checks or restrictions on the type of use.

## Pro Support

An annual support subscription for organizations that need predictable
response times, prioritized fixes and procurement documents.

This is a services agreement, not a software license. The software remains
under GPLv2: the customer may use the Community build without a subscription,
and fixes made under the subscription go into public releases (the customer
may receive them earlier).

### Included

- SLA for response time and priority (see the table below);
- prioritized fixes for regressions and vulnerabilities;
- prioritization of feature requests (no guarantee of delivery);
- corporate deployment artifacts: SHA-256 checksums, silent install
  parameters, Intune/PDQ guidance; signed builds and an SBOM once a
  certificate is obtained and generation is enabled in CI;
- invoice, contract, PO, VAT ID and reverse charge, closing documents;
- named contact and an onboarding call at subscription start.

### Not included

- custom development — separate day rate;
- a guarantee that specific features will be delivered;
- support for modified builds and forks;
- indemnity by default — handled under a separate agreement;
- support for platforms not listed in README.

## SLA

| Severity | Example | Response | Target fix |
|---|---|---|---|
| P1 | crash, data loss, blocks work | 1 business day | workaround or patch on a commercially reasonable efforts basis |
| P2 | key feature broken, workaround exists | 3 business days | next scheduled release |
| P3 | questions, cosmetics, feature requests | 5 business days | no target date |

- Business hours: Mon–Fri, 10:00–18:00 UTC+3, excluding public holidays.
- Languages: English, Russian.
- Channel: email or the support portal specified in the contract.
- Response time is measured from receipt of the request during business hours.
- Target fixes are a commitment to use commercially reasonable efforts, not a
  guaranteed deadline.

## Supported versions

- The latest stable release and the previous minor release are supported
  (N and N-1).
- Fixes ship in the latest supported release; only security fixes and critical
  regressions are backported to N-1.
- Pre-release and RC builds, as well as modified builds, are not supported.
- Older versions are supported on a reasonable-efforts basis; upgrading to a
  supported release is recommended.
- Community support follows the same version policy.

## Support data

- Application logs are sufficient for diagnostics; a settings export may be
  requested when needed.
- Logs may contain profile names, wallpaper file paths, monitor and audio
  device names, process names and error text.
- A settings export may additionally contain window titles, pinned
  applications and hotkey bindings.
- Data received through support channels (email, portal) is used only to
  diagnose and fix the request, is not shared with third parties except where
  required by law, and is deleted 90 days after the request is closed.
- GitHub Issues posts and attachments are public; do not post secrets or
  personal data there.
- Remote access and screen sharing require the customer's explicit consent.
- The customer provides data voluntarily and may remove unnecessary personal
  information and secrets before sending it.
- For Pro Support, data processing is governed by the contract; for Community,
  by this section and GitHub's terms.

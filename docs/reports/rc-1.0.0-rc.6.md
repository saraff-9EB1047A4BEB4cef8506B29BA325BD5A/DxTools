# Отчёт 1.0.0-rc.6 — контекстное меню панели задач

Дата: 2026-11-21.

## Цель

Добавить в кнопки панели задач команды переноса указанного окна на выбранный
монитор и возврата окна на текущий монитор для основной и дополнительных
панелей задач.

## Реализовано

- `AppSettings`: `EnableTaskbarContextMenu` (по умолчанию включено) и
  `EnablePrimaryTaskbarMenu` (opt-in), схема настроек 10.
- `WindowManager.MoveWindowToMonitor` и `TryGetMonitorIndex`; общий расчёт
  позиции/DPI/topmost/maximized вынесен в один путь с горячими клавишами.
- `WindowMatcher`: сопоставление кнопки панели задач (UI Automation) с окнами
  по AUMID (`GetApplicationUserModelId`/`IPropertyStore`), точному заголовку,
  имени exe, FileDescription и частичному совпадению.
- Контекстное меню кнопок панелей задач DxTools (вторичные мониторы и сплиты):
  `Переместить на монитор ▸`, `Вернуть на этот монитор`, выбор окна в группе,
  настройки DxTools; pinned-only — запуск приложения.
- Основная панель Windows: `PrimaryTaskbarMenuService` по Ctrl+правому клику.
  Нативный LL-mouse-hook (C ABI v5) подавляет только пару RBUTTONDOWN/UP над
  панелью, UI Automation определяет кнопку, меню DxTools показывает команды.
  Штатное меню Windows не изменяется, инъекций в explorer.exe нет.
- Трей: подменю `Перенести активное окно на монитор` с отметкой текущего.
- Настройки в UI, строки RU/EN, стили `ContextMenu`/`MenuItem` для светлой
  и тёмной тем.
- 6 unit-тестов `WindowMatcher`/настроек; всего 41 тест.

## Ограничения

- Windows 11 не предоставляет поддерживаемого API для добавления пунктов в
  штатное меню кнопок панели задач; поэтому на основной панели используется
  отдельное меню DxTools по Ctrl+ПКМ (включается в настройках).
- Распознавание кнопки опирается на UI Automation и эвристики сопоставления;
  для нестандартных приложений/вкладок возможна ошибка — предусмотрен выбор
  окна из списка и fallback через меню панели DxTools/трея.
- При автоскрытии/перемещении основной панели прямоугольник хука обновляется
  по `WM_DISPLAYCHANGE` и таймером раз в 5 секунд; в редких случаях до
  обновления возможен пропуск жеста.

## Проверка

- `dotnet build DxTools.sln -c Debug/Release` — успешно, 0 предупреждений.
- `dotnet test DxTools.sln -c Debug/Release` — 41/41.
- `build/build-native.ps1` — native DLL и shell extension собраны portable Zig
  для x64 и ARM64 (эквивалент MSVC-сборки в CI).
- Native probe на собранной DLL: `api=5, ping=True, version=0.7.0`.
- UIA-проверка реальной панели задач: все кнопки приложений (Edge, eXpress,
  Диспетчер задач, Nomad.NET, Яндекс.Музыка, VS Code, Unigram, Блокнот,
  spacedesk) сопоставлены с окнами; AUMID берётся через
  `GetApplicationUserModelId`/`IPropertyStore`.
- End-to-end smoke: Release-сборка запущена с временными настройками;
  синтетический Ctrl+ПКМ по кнопке Edge открыл WPF-меню над кнопкой
  (`rect=121,893,355,1056` при кнопке в (121,1056)), dispatcher-исключений нет.
  Для меню используется offscreen popup-host с `WS_EX_TOOLWINDOW|NOACTIVATE|TRANSPARENT`,
  чтобы позиционирование работало при скрытом главном окне.

Ручная матрица (2–3 монитора, mixed DPI, автоскрытие, сплиты, elevated-окна,
RU/EN, тёмная/светлая тема, перезапуск explorer) остаётся на приёмку.
